# leader — Claude 带队，AI 包工队施工

让 Claude 当项目经理：你只说"我要什么"，它负责扫盘、拆任务、写任务书，把活派给各家 AI CLI（默认支持 Cursor 的 Grok、Codex、Kimi），在隔离的 git worktree 里施工，最后由 Claude 验收、合并、交房。

适合：有多个 AI 订阅，想让"贵的脑子只做判断（计划/审查），便宜的脑子做体力（实现/杂活）"的人。

## 前置条件

- Claude Code（本 skill 的运行载体）
- git
- 至少一个"小弟"CLI，装好**并登录**：
  - [Cursor CLI](https://cursor.com)（`cursor-agent`）
  - [Codex CLI](https://github.com/openai/codex)（`codex`）
  - [Kimi CLI](https://www.kimi.com/code)（`kimi`）
  - 少装哪个都行，`crew.md` 里把对应工种标成「未安装」即可

## 安装

把整个 `leader` 目录拷到 Claude Code 的 skill 目录：

```bash
cp -r leader ~/.claude/skills/leader
```

## 装后三步（重要）

1. **对 Claude 说一句：「检查包工队到岗情况」**——让它逐个工种跑冒烟测试（空目录建文件并亲眼确认），到的上岗、没到的标注。
2. **改模型名**：`crew.md` 调用模板里的模型名是示例默认值，让它换成你账号里实际可用的（或直接把账号情况告诉它，让它自己改）。
3. **改称呼（可选）**：skill 里统称你"老板"，想换称呼让 AI 全局替换即可。

## 日常使用

直接说人话即可触发，例如：

- 「派活：把 backlog 里这几项做了」
- 「排个计划派下去」
- 「这个 bug 找人修一下」

中途随时可以插手，也是说人话：

- 「现在进度如何」——工头汇报各卡状态
- 「停掉 XX 那个活」——立刻叫停对应工人
- 「XX 做得不对，让它重做」——打回返工

## 扩编（加新 CLI）

对 Claude 说：「把 XX CLI 加进包工队」。

它会按 `crew.md` 第六节的协议走：确认可非交互调用 → 补工种表 → 写调用模板 → **冒烟测试通过才算上岗**。比如接入 opencode、Pi Agent 等，都是一句话的事。

## 换其他 CLI 当工头（进阶）

默认工头是 Claude，但 `SKILL.md` 本质是一份工具无关的操作手册——任何能读文件、能跑 shell 命令的 agent（如 Codex CLI）都能照着当工头。要换帅，做两件事：

1. **把手册交给新工头**：其他 CLI 没有 Claude Code 的 skill 自动加载机制，把 `SKILL.md` + `crew.md` 的内容手贴给它，或放进它自己的 prompt/规则文件里。手册里的「我」就是读它的那个工头。
2. **Claude 降格为工人**：`crew.md` 里已备好 `claude -p` 调用模板，Claude 转任「疑难杂症专家」——bug 病根诊断、方案取舍、新工头啃不动的硬骨头升级给它。

一个提醒：这套设计的前提是「**最聪明的脑子当工头**」——拆任务、写任务书、验收把关是质量命门，体力活才外包。换帅之前，建议先拿几张小卡试一轮，重点看新工头的验收能不能看住（比如能不能识破"读源码字符串冒充行为断言"的假测试），再决定放不放权。

## 文件结构

- `SKILL.md` — 铁律 + 完整流程（扫盘 → 派活 → 验收 → 返工 → 合并 → 交房）
- `crew.md` — 工种表：谁擅长什么、调用模板、已知坑、实战记录、新 CLI 接入协议

## 核心机制速览

- **95% 把握度才开工**：需求含糊先问老板，不用"合理默认"糊弄
- **包工队绝不碰 git**：提交合并全由 Claude 亲手做
- **不信自我汇报**：只认 `git diff` + 真实测试 + 真实运行
- **隔离样板间**：每个活独立 git worktree，互不干扰
- **返工双轨制**：bug 跨工种轮转（事不过三），功能同工种最多打回两次
- **UI 先图后码**：生图草图 → HTML 示意稿老板拍板 → 才写代码
